# AC-17975: Los problemas de compatibilidad con PHP 8.5 afectan a los comandos CLI, la edición de categorías, la configuración de diseño y el inicio de sesión del cliente

El parche AC-17975 soluciona el problema donde los comandos CLI, la edición de categorías, la configuración de diseño y el inicio de sesión del cliente de AJAX fallan en Adobe Commerce 2.4.9 cuando se utiliza PHP 8.5. Esta revisión está disponible cuando está instalado [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83. El ID del parche es AC-17975. Este problema está programado para solucionarse en Adobe Commerce 2.4.9-p1 y 2.4.10.

## Productos y versiones afectados

**El parche se ha creado para la versión de Adobe Commerce:**

* Adobe Commerce (todos los métodos de implementación) 2.4.9

**Compatible con versiones de Adobe Commerce:**

* Adobe Commerce (todos los métodos de implementación) 2.4.9

>[!NOTE]
>
>El parche podría ser aplicable a otras versiones con las nuevas versiones de [!DNL Quality Patches Tool]. Para comprobar si el parche es compatible con su versión de Adobe Commerce, actualice el paquete `magento/quality-patches` a la última versión y compruebe la compatibilidad en la página [[!DNL Quality Patches Tool]: buscar parches &#x200B;](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=es). Utilice el ID de parche como palabra clave de búsqueda para localizar el parche.

## Problema

Los comandos CLI, la edición de categorías, la configuración de diseño y el inicio de sesión del cliente de AJAX fallan cuando Adobe Commerce 2.4.9 se ejecuta en PHP 8.5.

<u>Requisitos previos</u>:

PHP 8.5 está instalado.

<u>Pasos a seguir</u>:

1. Ejecute el siguiente comando de CLI:

   ```
   bin/magento --version
   ```

1. En la tienda, complete un cierre de compra e inicie sesión durante el cierre de compra mientras que el CAPTCHA del cliente está habilitado para el inicio y el cierre de compra.
1. En el Administrador, abra una categoría cuando un atributo de categoría tenga `frontend_input` establecido en `null`.
1. En el Administrador, vaya a **[!UICONTROL Content]** > **[!UICONTROL Design]** > **[!UICONTROL Configuration]** y, a continuación, haga clic en **[!UICONTROL Edit]** en la columna **[!UICONTROL Action]** para ver una tienda.


<u>Resultados esperados</u>:

Todas las operaciones se completaron correctamente.


<u>Resultados reales</u>:

Las operaciones fallan con errores, como:

```
Exception #0 (Exception): Deprecated Functionality: Using null as an array offset is deprecated, use an empty string instead
/var/www/html/vendor/magento/framework/App/Config/ScopeCodeResolver.php on line 62
```

```
report.CRITICAL: Exception: Deprecated Functionality: Using null as the key parameter for array_key_exists() ... in module-captcha/Helper/Data.php on line 92
```

```
There is an error in vendor/magento/framework/Setup/Mvc/MvcApplication.php at line: 170
Undefined constant "Magento\Framework\Setup\Mvc\GLOB_BRACE"
```

```
Deprecated Functionality: Using null as an array offset is deprecated, use an empty string instead in
var/www/html/app/code/Magento/Catalog/Model/Category/DataProvider.php on line 41
```
