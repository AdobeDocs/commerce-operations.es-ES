# ACP2E-4799: La consulta de GraphQL `requisition_lists` devuelve `total_count` incorrecto con la paginación

La revisión ACP2E-4799 corrige el problema en el que la consulta de GraphQL `requisition_lists` devuelve un valor `total_count` incorrecto que refleja únicamente el número de elementos de la página actual en lugar del número total de entidades de lista de solicitudes que coinciden con los criterios de consulta. Esta revisión está disponible cuando está instalado [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.82. El ID del parche es ACP2E-4799. Este problema está programado para solucionarse en Adobe Commerce B2B 1.5.4.

## Productos y versiones afectados

**El parche se ha creado para la versión de Adobe Commerce:**

* Adobe Commerce (todos los métodos de implementación) B2B 1.5.2-p4

**Compatible con versiones de Adobe Commerce:**

* Adobe Commerce (todos los métodos de implementación) B2B >=1.5.0 &lt;1.5.3

>[!NOTE]
>
>El parche podría ser aplicable a otras versiones con las nuevas versiones de [!DNL Quality Patches Tool]. Para comprobar si el parche es compatible con su versión de Adobe Commerce, actualice el paquete `magento/quality-patches` a la última versión y compruebe la compatibilidad en la página [[!DNL Quality Patches Tool]: buscar parches &#x200B;](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=es). Utilice el ID de parche como palabra clave de búsqueda para localizar el parche.

## Problema

Cuando los clientes consultan listas de solicitudes con paginación, el campo `total_count` no refleja el número completo de listas de solicitudes coincidentes. Lo único que hace es informar sobre el número de elementos devueltos para la página actual, lo que hace que los metadatos de la paginación sean inexactos.

<u>Requisitos previos</u>:

Las listas de solicitudes están habilitadas para Adobe Commerce B2B.

<u>Pasos a seguir</u>:

1. En el Administrador, vaya a **[!UICONTROL Stores]** > **Configuración** > **Configuración**.
1. En el panel izquierdo bajo **General**, elija **Características B2B**.
1. Establezca **[!UICONTROL Enable Requisition List]** en **[!UICONTROL Yes]** y seleccione **[!UICONTROL Save Config]**.
1. Inicia sesión en la tienda como cliente.
1. Elija **[!UICONTROL My Requisition Lists]** y cree seis listas de solicitudes.
1. Asegúrese de que el cliente tenga exactamente seis listas de solicitudes y de que cada nombre de lista contenga `ABC`, de modo que las seis listas coincidan con la consulta filtrada.
1. Ejecute la siguiente consulta de GraphQL con `pageSize` establecido en dos y `currentPage` establecido en uno:

   ```graphql
   query {
     customer {
       requisition_lists(
         pageSize: 2
         currentPage: 1
       ) {
         items {
           uid
           name
         }
         total_count
         page_info {
           current_page
           page_size
           total_pages
         }
       }
     }
   }
   ```

1. Ejecute esta consulta de GraphQL:

   ```graphql
   query {
     customer {
       requisition_lists(
         filter: { name: { match: "%ABC%" } }
         pageSize: 2
         currentPage: 1
       ) {
         items {
           uid
           name
         }
         total_count
         page_info {
           current_page
           page_size
           total_pages
         }
       }
     }
   }
   ```


<u>Resultados esperados</u>:

* La consulta `requisition_lists` devuelve `total_count` igual al número total de listas de solicitudes propiedad del cliente, independientemente de `pageSize` y `currentPage`.
* Los datos de paginación siguen siendo coherentes con el conjunto de resultados coincidente completo.

<u>Resultados reales</u>:

`total_count` devuelve solamente el número de elementos en la página actual, como dos en lugar de seis.
