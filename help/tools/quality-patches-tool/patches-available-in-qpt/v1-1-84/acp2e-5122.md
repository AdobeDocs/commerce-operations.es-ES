# ACP2E-5122: Los errores de carrito de GraphQL gestionados se escriben incorrectamente en el registro de excepciones

El parche ACP2E-5122 corrige el problema en el que los errores de solicitud del carro de compras de GraphQL gestionados se escriben en el registro de excepciones como errores de aplicación. Esta revisión está disponible cuando está instalado [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84. El ID del parche es ACP2E-5122. Este problema está programado para solucionarse en Adobe Commerce 2.4.10.

## Productos y versiones afectados

**El parche se ha creado para la versión de Adobe Commerce:**

* Adobe Commerce (todos los métodos de implementación) 2.4.8-p5

**Compatible con versiones de Adobe Commerce:**

* Adobe Commerce (todos los métodos de implementación) 2.4.4 - 2.4.9

>[!NOTE]
>
>El parche podría ser aplicable a otras versiones con las nuevas versiones de [!DNL Quality Patches Tool]. Para comprobar si el parche es compatible con su versión de Adobe Commerce, actualice el paquete `magento/quality-patches` a la última versión y compruebe la compatibilidad en la página [[!DNL Quality Patches Tool]: buscar parches &#x200B;](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=es). Utilice el ID de parche como palabra clave de búsqueda para localizar el parche.

## Problema

Los errores de solicitud del carro de compras de GraphQL administrados se escriben en el registro de excepciones como errores de aplicación.

<u>Pasos a seguir</u>:

1. Envíe una mutación de GraphQL `placeOrder` con un ID de carro de compras enmascarado no válido, caducado o ya destruido, como esta mutación:

   ```
       mutation {
           placeOrder(input: { cart_id: "test" }) {
               orderV2 {
                   id
                   number
               }
           }
       }
   ```

1. Compruebe la respuesta de GraphQL.
1. Busque en `var/log/exception.log` el error del carro de compras.

<u>Resultados esperados</u>:

1. La solicitud de GraphQL devuelve una carga de error de cliente controlada para el carro de compras no válido sin una respuesta *HTTP 500*.
1. La *GraphQlNoSuchEntityException* controlada no se escribe en `var/log/exception.log` y, en su lugar, se enruta a un canal de registro de gravedad inferior.

<u>Resultados reales</u>:

Cada solicitud escribe la excepción controlada en `var/log/exception.log` con una gravedad de `report.ERROR`, lo que provoca un crecimiento ilimitado del registro durante las solicitudes repetidas.
